# DECISIONS — AgentHR

Зафиксированные решения и компромиссы. Перед спорным выбором проверить этот файл;
новое решение — добавлять сюда, а не в `AGENTS.md`.

## Архитектура и стек

| Решение | Обоснование |
|---|---|
| Модульный монолит, не микросервисы | скорость разработки, минимум инфраструктуры |
| Deep Agents как основной Harness | готовый цикл, контекст, планирование, сабагенты, память; свои правила — middleware |
| LangGraph под капотом Deep Agents | явное состояние, checkpointing, контроль tool-calling |
| Дефолтный состав Deep Agents | файловые tools и сабагент `task` оставлены; своей мультиагентной логики в MVP нет |
| Postgres + pgvector, одна БД | меньше инфраструктуры; векторный поиск без второй системы |
| Граф в Postgres на MVP | реляционная модель; репозиторий-граница для будущей миграции на Neo4j/AGE |
| React + TS, не Python-UI | стриминг интервью, кастомные визуализации, кодогенерация |
| Без state-менеджеров | TanStack Query + `useState` закрывают потребности |
| JWT access + refresh | просто и стандартно |
| Упрощённый планировщик в MVP | полный топологический маршрут — позже |

## Данные и онтология

| Решение | Обоснование |
|---|---|
| Пайплайн M2: сервис + tools | извлечение и нормализация — детерминированный `app/services/analysis.py`; те же функции — tools агента |
| Онтология — словарь, не whitelist | навыки вне словаря не теряются и попадают в кандидаты/автотемы |
| TTL/CSV — источники, не готовая OWL-модель | в TTL нет иерархии, уровней и пререквизитов; они добавляются отдельными слоями |
| Provisional-темы | у каждого навыка всегда есть `topic_id`; неизвестный навык получает provisional-тему, алиас и кандидата |
| Backfill legacy NULL | миграция заполнила старые `topic_id`, затем `NOT NULL` и FK `RESTRICT` |
| Лимит `AUTO_TOPIC_LIMIT` | не даёт онтологии взрываться; overflow идёт в одну review-тему |
| Ревью через CLI | в проекте нет ролей/админ-аутентификации; CLI безопаснее публичного API |
| Автоматическое ревью provisional-тем | сначала правила (точный alias или близость ≥ `ONTOLOGY_AUTO_MERGE_SIMILARITY` → merge; упоминания в нескольких документах → approve), затем LLM только для спорных тем; `approve`/`merge` применяются при `confidence` ≥ `ONTOLOGY_AUTO_REVIEW_MIN_CONFIDENCE`, merge — только в top-5 кандидатов; решение `keep` и низкая уверенность уводят навык в общую canonical-тему «Прочее (авто-ревью)», поэтому ручная проверка пользователю не нужна; provisional остаётся только при недоступной LLM; аудит с `actor="auto"`; запуск best-effort после сохранения документа |
| Две метрики покрытия | `coverage_all` включает provisional, `confirmed_readiness` — только canonical |
| Группы `AND/OR` | `OR` — max, `AND` — min; для confirmed группа должна быть полностью canonical |
| Criticality и рубрика уровней | `must_have` / `nice_to_have`; `required_level` 0–100 по якорям; критический гейт — позже |
| Assessment MVP | 8 тем × 20 курируемых вопросов, тест из 10 (по 2 на сложность); single choice; детерминированный скоринг; один тест на тему без пересдачи; `claimed_level` из резюме и `verified_level` из теста; runtime-генерация вопросов LLM не используется |
| Локальные эмбеддинги | ONNX-модель без ключей и внешних сервисов; деградация к alias/fuzzy; таблица `embeddings` позже |
| Профиль-first | сначала резюме и профиль знаний, затем вакансия; резюме в форме вакансии не требуется; повторное резюме дополняет профиль, а не заменяет его |
| Резюме файлом | PDF/DOCX через `POST /resumes/upload`: `pypdf`/`python-docx`, лимит 5 МБ и защита от zip-бомб; файл не хранится, только текст; сканы без текстового слоя → 422 |
| План подготовки | темы только из резюме, 5–12 штук, сортировка `proficiency × (0.6 + 0.4 × confidence)`; вакансия влияет только на целевой уровень, но не на состав |
| Банк вопросов | полная генерация заранее по 90 seed-темам × 3 сложности × 5 вопросов; LLM-ответы кэшируются в БД, дедуп по fingerprint; повторный запуск добирает пропуски |
| ООП и алгоритмы в тестах | темы `oop` и `algorithms` всегда генерация вопросов, даже если их нет в резюме; в план они попадают только по общим правилам |
