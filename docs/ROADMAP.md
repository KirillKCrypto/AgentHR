## 3. Задачи по неделям

**Неделя 1 — Фундамент.**
Monorepo (`backend/`, `frontend/`, `infra/`) · Docker Compose (Postgres + pgvector) ·
FastAPI + `/health` · Alembic · JWT-auth · слой LLM со структурным выводом.
Frontend: React + TS + Vite, роутинг, shadcn/ui.
*Готово: поднимается одной командой, логин работает, LLM возвращает JSON по схеме.*

**Неделя 2 — Agent Harness.**
Deep Agents · checkpointer · реестр tools (JSON Schema) · исполнитель tool-calls ·
`agent_actions` · лимиты и таймауты · тесты на мок-LLM. Frontend: вход, каркас дашборда.
*Готово: с мок-LLM цикл проходит и пишет лог.*

**Недели 3–4 — Понимание кандидата.**
Онтология v2 (89 атомарных навыков, 75 пререквизитов) · извлечение навыков ·
нормализация · `user_skill_states` · gap-анализ · экраны загрузки и профиля.
*Готово: корректные навыки и профиль с пробелами.*

**Неделя 5 — Подготовка.**
Упрощённый планировщик · `learning_plans` / `plan_items` · API плана · экран плана ·
каркас сессии интервью (WebSocket).
*Готово: план строится, сессия создаётся.*

**Неделя 6 — Адаптивность.**
`next_question`, `evaluate_answer` (рубрики), `adjust_difficulty` · обновление графа ·
`interview_turns` · стриминг и карточка фидбека.
*Готово: диалог «вопрос → ответ → оценка → следующий вопрос».*

**Неделя 7 — Память и отчёт.**
`save_interview_result` + отчёт · `load_user_profile` · экран отчёта · дашборд прогресса ·
таблица `embeddings`.
*Готово: отчёт есть, новая вакансия видит прошлый опыт.*

**Неделя 8 — Демо.**
E2E-тест · mini-eval (3–5 эталонов) · багфикс · тестовые данные · README · демо-прогон.

## 4. Критический путь

```text
Agent Harness → Извлечение → Профиль → Интервью (оценка + адаптация) → Память
```

Если отстаём — режем UI-полировку, E2E и дашборды, **но не цикл агента**.

## 5. Frontend: 7 экранов

| Маршрут | Назначение | Ключевое | Неделя |
|---|---|---|---|
| `/login` | Вход / регистрация | форма, токен, редирект | 2 |
| `/` | Дашборд | «Новая подготовка», вакансии, план, сессии | 2–3 |
| `/vacancies/new` | Загрузка вакансии и резюме | текст, «Анализировать», навыки | 3 |
| `/profile` | Профиль знаний | темы 0–100%, пробелы, источник | 4 |
| `/plans/:id` | План подготовки | чек-лист тем, «Пройти интервью» | 5 |
| `/interview/:id` | Тренировочное интервью | чат, стриминг, фидбек | 5–6 |
| `/reports/:id` | Отчёт | средний балл, слабые темы, рекомендации | 7 |

Служебные: 404, ошибка соединения, общий лоадер.

**Правила фронтенда:** 6–7 экранов · без state-менеджеров · один типизированный
API-клиент (типы из OpenAPI) · один хук `useInterviewSocket` · фиксированные версии ·
UI только из shadcn/ui · явные состояния `loading / error / empty / ready`.

**Запрещено:** анимации, кастомный drag&drop, canvas/графы руками, i18n,
тёмная тема, мобильный адаптив.

## 6. Тестирование

- **Функциональное:** REST/сервисные тесты, golden-наборы вакансий и резюме, CRUD, auth.
- **Агентское:** цикл за N шагов; корректный выбор tools (мок-LLM); валидация схем;
  audit-лог пишется всегда; откат при ошибке инструмента.
- **Сценарное (e2e):** все 7 шагов сценария; повторная вакансия использует профиль;
  параллельные сессии.
- **Адаптивность:** синтетические пользователи (слабый SQL / сильный Python);
  регрессия оценок после N сессий; согласованность с эталоном.
- **Качество LLM:** eval-наборы на извлечение (precision/recall) и оценку ответов.

## 7. Риски и решения

| Риск | Решение |
|---|---|
| Точность оценки ответов | рубрики + структурный вывод + самоконсистентность + калибровка; хранить `confidence` и `evidence` |
| Качество онтологии | узкая курируемая онтология; расширение через ревью; версионирование |
| Застревание / дороговизна agent-loop | лимиты итераций и бюджета, таймауты, checkpointing, дешёвая модель, fallback |
| Дрейф профиля | взвешенное обновление по `source`, decay, пересчёт по истории |
| Раздувание контекста | суммаризация, срез графа, RAG вместо «всё в промпт» |
| Рассинхрон графа и БД | единая транзакция; граф — источник расчётов, `user_skill_states` — срез |
| Приватность | AuthN/AuthZ, изоляция по `user_id` в tools, шифрование чувствительных данных |
| Латентность стрима | стриминг токенов, очередь, отдельный воркер, кэш эмбеддингов |
| Потеря контекста между сессиями | фиксация состояния в БД/checkpoint, короткие спринты, Definition of Done |
| Скоуп-крип | замороженный MVP-список; отложенные фичи не тянуть |
